# Leaderboard — Terraform

Automates the manual "Leaderboard Foundation" lab end-to-end:

- **DynamoDB**: `leaderboard-scores` (with the `leaderboard-rank-index` GSI) + `leaderboard-snapshots`
- **IAM**: one `iam_role_lambda` role (DynamoDB full access + basic Lambda execution), reused by all 5 functions
- **Lambda**: 5 functions built with the [`terraform-aws-modules/lambda/aws`](https://github.com/terraform-aws-modules/terraform-aws-lambda) community module (handles zipping + permissions, no hand-written `archive_file`/`aws_lambda_permission` boilerplate)
- **API Gateway (REST)**: 5 endpoints, Lambda proxy integration + CORS, deployed to a `prod` stage
- **EC2 + Nginx**: dashboard host, provisioned by Terraform; the `/www` files are pushed onto it by a dedicated bash script

## Layout

```
deploy.sh              # terraform apply, then pushes the frontend
destroy.sh             # tears everything down
terraform/             # all infra: iam.tf, dynamodb.tf, lambda.tf, apigateway.tf, ec2.tf, ...
lambda/                # the 5 handler.py sources (unchanged), one folder per function
scripts/setup-www.sh   # renders env.js + scp's www/html onto the EC2 host
www/html/               # index.html (simple black & white frontend) + env.js.tpl
```

## Prerequisites

- Terraform >= 1.5
- AWS credentials configured (`aws configure` or environment variables)
- `ssh`, `scp`, `sed` (standard on macOS/Linux; use WSL or Git Bash on Windows)

## Deploy

```bash
./deploy.sh
```

This runs `terraform init && terraform apply`, waits for the EC2 instance to come up,
then runs `scripts/setup-www.sh`, which:

1. Reads the API Gateway invoke URL and dashboard IP from Terraform outputs
2. Renders `www/html/env.js.tpl` → `env.js` with the real `API_BASE`
3. Copies `index.html` + `env.js` onto the instance's `/var/www/html`
4. Removes the default nginx page and restarts nginx

At the end you'll see the API URL and dashboard URL printed.

## Run it by hand

If you'd rather run the steps yourself:

```bash
terraform -chdir=terraform init
terraform -chdir=terraform apply
./scripts/setup-www.sh
```

`scripts/setup-www.sh` can be re-run any time you change `www/html/index.html` —
it's idempotent.

## Notes

- A fresh SSH key pair is generated by Terraform (`tls_private_key` + `aws_key_pair`)
  and written to `./leaderboard-key.pem` — this is what `setup-www.sh` uses to reach
  the instance, so you don't need to bring your own key.
- `var.ssh_allowed_cidr` defaults to `0.0.0.0/0` for convenience. Restrict it to your
  own IP (e.g. `"203.0.113.4/32"`) via a `terraform.tfvars` file before using this
  anywhere but a throwaway lab account.
- Table names, the IAM role name, and the API's 5 routes match the original manual
  README exactly, so the Lambda source code didn't need any changes.

## Test it

Once deployed, open `http://<dashboard_public_ip>` and:

1. Click **Seed data** to generate test players
2. Confirm the leaderboard is sorted highest → lowest
3. Switch between **All time / Today / This week**
4. Use the **Player** tab to look up an individual player's rank & percentile
5. Use **Submit** to post a new score and see it reflected after a refresh
